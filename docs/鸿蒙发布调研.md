> 调研日期:2026-09-01(信息口径以 2025~2026 年最新可得资料为准)
> 被发布对象:纯 Java、零第三方依赖、免 Gradle 构建链的安卓工具 APP(照片转拼豆图纸;含 ONNX Runtime 本地推理、相机/相册、PDF 导出、无蓝牙;约 11MB;minSdk 24 / targetSdk 34)

## 一、旧版路径:HarmonyOS 4.x 及以下(兼容安卓的鸿蒙)

### 1.1 现状:AppGallery 仍然接受 Android APK 上架

- 华为应用市场(AppGallery)对搭载 HarmonyOS 4.x/4.3 及 EMUI 的设备继续分发安卓 APK 应用,新 APK 应用仍可上架。2025 年仍有完整的安卓应用上架全流程文章;2026 年华为官网《华为应用市场 2025 年度安全与隐私治理报告》仍以"每款 App 须按规则通过审核"描述其分发业务。**【较确定】**(来源 17、18、19)
- 技术门槛:华为要求新上架安卓应用的 targetSdk ≥ 30(2023-10-31 起执行,此后存量不合规应用被清理)。本 APP targetSdk 34,满足。**【确定】**(来源 20)
- 需要注意:华为力推"鸿蒙原生",应用市场上同一名下可以同时挂鸿蒙版与安卓版;不提交鸿蒙版不会被强制下架安卓版(目前未见任何"必须交鸿蒙版"的强制政策)。**【较确定】**(综合来源 4/17,无反例)

### 1.2 个人开发者能否上架:能

- 华为开发者账号分"个人"与"企业"两类,个人完成实名认证(人脸识别/银行卡/人工审核/华为云授权四选一)即可开发、签名、发布应用;注册免费。**【确定】**(华为官方《实名认证介绍》文档,来源 5;实操文章来源 21)
- 与小米等"不支持个人开发者上传"的商店不同,华为应用市场接受个人开发者上架(历史攻略与 2025 年文章均以个人身份操作)。**【较确定】**(来源 17、22、23)

### 1.3 资质要求:软著(版权证明)+ APP 备案

1. **软件著作权/版权证明**【较确定】
   - 华为审核上架时要求提供版权证明,两种任选其一:《计算机软件著作权登记证书》(国家版权登记,官方渠道免费、下证约 30~60 个工作日)或第三方《APP 电子版权认证证书》(最快当天,仅作上架凭证)。版权证明中的软件名称须与上架应用名一致,否则驳回。委托/合作开发可用授权协议替代。**【较确定】**(来源 23、24、25、26)
   - 官方佐证:华为官方《鸿蒙原生应用开发者激励计划操作指导》明确提供"如您缺少上架应用需要的'软著'"的免费办理渠道——即官方默认上架需软著。**【较确定】**(来源 4)
   - 例外:个别商店/个别类别可豁免,但华为总体从严,建议按"必须有"准备。**【不确定】**(豁免边界无官方清单)
2. **APP 备案(工信部"核准")**【确定】
   - 政策依据:《工业和信息化部关于开展移动互联网应用程序备案工作的通知》(工信部信管〔2023〕105号,成文 2023-07-21):境内从事互联网信息服务的 APP 主办者必须备案;"网络接入服务提供者、分发平台、智能终端生产企业不得为未履行备案手续的 APP 提供网络接入、分发、预置等服务";新 APP"先备案后开展业务",存量 APP 于 2023-09~2024-03 补备案,2024-04 起转入监督检查。**【确定】**(来源 1、2)
   - 实操:个人开发者通过云服务商(阿里云/腾讯云/华为云等)提交 APP 备案,通常需要一个已备案域名 + 一台国内服务器/接入商,费用约 100~300 元/年;APP 内须标注备案编号。**【较确定】**(来源 27、28)
   - 华为执行:华为官方《APP核准(APP备案)指引》(2026-06-25 更新)与《应用审核指南》(2026-07-24 更新)把"APP 未核准(备案)"列为常见驳回原因。**【确定】**(来源 3、29)
   - 纯离线 APP 的合规边界:105 号文针对"从事互联网信息服务的 APP";完全离线、无任何后端域名的 APP 在"自建网站提供下载"场景下是否必须备案存在灰色地带,但**只要想上任何国内应用商店(含 AppGallery),备案是硬门槛**。稳妥做法是完成备案。**【不确定】**(边界解释无官方细则)
3. **特殊类别**:工具类 APP 无行业许可证要求(金融/新闻/医疗等才需要)。**【较确定】**(来源 23)

### 1.4 审核要点(工具类)

华为官方《应用审核指南》强调:功能真实完整、与描述一致;防止"功能单一、同质化、缺少价值"的应用;隐私政策、权限最小化、备案齐全;2025 年华为还上线了专门的审核规则课程。**【较确定】**(来源 3、30)
对本 APP:功能有独特价值(照片→拼豆图纸),非同质化模板应用;注意隐私政策文案、相册/相机权限申请说明即可。

### 1.5 HMS Core 是否强制:否

普通 APK 不集成 HMS Core 也能上架 AppGallery 并正常运行;只有用到华为推送、账号、地图、IAP 等能力才需要 HMS SDK。**【较确定】**(上架攻略与政策中均无"必须集成 HMS"条款,来源 17/22;官方审核指南亦未列该要求)

### 1.6 不通过应用市场的分发:可行

- HarmonyOS 4.x/4.3 兼容安卓运行时,可直接安装 APK:需对安装来源(浏览器/文件管理器)授予"安装未知来源应用"权限,并**关闭"纯净模式"**(否则提示"该应用来源未知,暂不支持下载"或报"恶意安装来源")。**【确定】**(来源 31、32、33)
- 因此"自建官网提供 APK 下载"对本 APP 完全可行;合规上若 APP 纯离线、网站备案齐全,风险很低;若走正规化,补一个 APP 备案即可。**【较确定】**(见 1.3 合规边界讨论)
- 局限:鸿蒙 4.x 用户基本只存在于存量华为/荣耀(部分)机型,该用户群随系统升级 NEXT 逐年萎缩,自分发 APK 也没有应用市场的流量。**【较确定】**

### 1.7 小结(旧路径)

个人开发者 **可以** 无企业资质上架 AppGallery 的安卓 APK:账号免费、个人实名即可;需准备 软著(或电子版权证书)+ APP 备案;targetSdk 34 达标;无 HMS 强制;商店外还可走官网 APK 自分发。投入主要是资质办理时间(软著 1~2 个月或电子证书数天)与备案(2~4 周),开发侧**零改动**。

## 二、纯血鸿蒙路径:HarmonyOS NEXT(5.0+,及 6/7)

### 2.1 只接受原生 HAP,APK 彻底出局

- HarmonyOS NEXT(5.0)起系统移除 AOSP 兼容层,不能安装、不能运行任何安卓 APK;尝试打开 APK 会直接提示无法打开。HarmonyOS 7 进一步彻底移除残余安卓兼容代码。**【确定】**(来源 14、15、16、34、35)
- NEXT 上也没有面向普通用户的"侧载"通道:应用只能通过 AppGallery 分发(签名校验),个人开发者无法像安卓那样把 HAP 放到网站让人下载安装(DevEco 真机调试仅限开发者自己的设备)。**【较确定】**(来源 34、21;未见任何官方/可信的 NEXT 侧载 HAP 方法)
- 过渡方案"卓易通"(第三方安卓兼容容器)可在部分 NEXT 设备上运行部分安卓应用,但兼容性差、非华为官方方案,不能作为发布路径。**【较确定】**(来源 36)

### 2.2 ArkTS 原生开发:最小可行动方案与代码迁移现实

- UI 层必须用 **ArkTS + ArkUI** 声明式范式重写,Android View/XML 体系无法复用;**没有官方"Java/Android→ArkTS"自动转换工具**(DevEco Studio 只提供工程模板、语法检查与部分知识库辅助)。**【较确定】**(来源 37、38)
- 业务逻辑:ArkTS 基于 TypeScript,本 APP 的纯 Java 图像算法(颜色量化、抖动、网格化等零依赖逻辑)可**人工翻译**为 TS/ArkTS,工作量可控;若追求性能,也可用 **HarmonyOS NDK(C/C++)** 重写热点代码。**【较确定】**
- 跨端方案的现状(评估为"对存量 Java 工程帮助有限"):
  - **Flutter for OpenHarmony**:OpenHarmony-SIG 维护的移植版(主线基于 Flutter 3.7.12,另有 3.22.1 适配分支),可构建 HAP,但 Flutter 官方并不支持 OHOS;gitee 仓库已归档迁至 GitCode。对现有纯 Java(非 Flutter)项目无复用价值,仅在未来跨端新项目时考虑。**【确定】**(来源 39)
  - **React Native for OpenHarmony(ohos_react_native)**:2024 年 9-10 月由 OpenHarmony-SIG 开源,基于 RN 0.72 分支,暂不支持 Bridgeless 等新特性;同样对本项目无复用价值。**【较确定】**(来源 40)
  - **uni-app x(DCloud)**:官方文档明确支持"鸿蒙"发布目标,VDOM 模式编译为 **ArkTS**(蒸汽模式运行于 ArkTS 引擎),HarmonyOS 5.0 起支持,最低 API 14/20;文档更新至 2026-09-01。适合"一套代码多端"的新项目,但把现有原生 Java APP 迁到 uni-app x 同样是整体重写。**【确定】**(来源 41)
- **结论**:对"纯 Java 原生安卓"APP,任何路线都绕不开"用 ArkTS 重写 UI + 翻译逻辑",跨端框架只能选一个重写载体,不能省掉重写本身。

### 2.3 个人开发者:注册、实名、证书签名——不需要企业资质

- 注册流程:注册华为账号 → 华为开发者联盟(developer.huawei.com)选"个人开发者" → 实名认证(人脸识别即时通过)→ 即可使用 DevEco Studio、AGC、签名等全部服务。**【确定】**(来源 5、21)
- 签名:HarmonyOS 全部应用必须签名(调试签名/发布签名,SHA256withECDSA)。个人开发者可通过 DevEco 自动签名完成真机调试;发布时在 AGC 生成本地 .p12/.csr → 申请发布证书 .cer 与 Profile .p7b → 手动/自动签名出包。全流程个人可独立完成,无企业资质要求,无付费环节(证书默认有效期 25 年)。**【确定】**(来源 21、42)
- 与安卓时代不同点:APK 时代签名是自签自证;NEXT 时代发布包必须使用 **华为 AGC 签发的发布证书**,这是商店分发强约束。**【确定】**(来源 42)
- **个人开发者能否上架 NEXT 应用:能。**官方《鸿蒙原生应用开发者激励计划操作指导》明确面向"个人/企业开发者";2024 年"1.3 万个应用上架原生鸿蒙"的报道也确认激励计划同时面向个人开发者;大量 2025~2026 个人开发者全流程实操(注册→实名→签名→上架)文章佐证。**【较确定】**(来源 4、43、44、21;华为个别文档页需登录查看,建议上架前在 AGC 帮助中心复核最新条款)

### 2.4 AppGallery Connect(AGC)上架流程【较确定】

官方流程(与安卓应用共用控制台):
1. AGC 创建应用(选择平台:HarmonyOS 应用/安卓应用),填写应用信息;
2. 准备资质:软著/版权证明、APP 备案(核准)编号、隐私政策网址、图标截图等;
3. 上传签名后的 **APP 包(App Pack,内含 HAP)**——开发期用 HAP,商店分发用 .app 包;
4. 提交审核 → 通过后发布(可选定时/分阶段)。
(来源 3、4、21、45;AGC 文档为 JS 渲染,具体入口以 developer.huawei.com 文档中心为准)

### 2.5 上架审核对工具类 APP 的要求【较确定】

- 硬材料:软著/版权证明(必填项)、APP 备案号、隐私政策;名称与版权证明一致。**【较确定】**(来源 4、23、44)
- 审核关注:功能与描述一致、真实可用、防同质化/低质模板应用;权限最小化与隐私合规。**【较确定】**(来源 3、30)
- 工具类无行业资质门槛;华为对个人开发者的 NEXT 应用无额外企业资质要求。**【较确定】**

### 2.6 ONNX Runtime 本地推理的兼容性(本项目最大技术风险)

- **官方支持矩阵:ONNX Runtime 官方不支持 HarmonyOS/OpenHarmony**(onnxruntime.ai 兼容性文档只列 Windows/Linux/macOS/Android/iOS)。**【确定】**(来源 6)
- **Android NDK 编译的 .so 不能直接放进 HAP 使用**:HarmonyOS NEXT 的用户态 libc 是 musl(非 Android bionic),NDK 工具链目标为 `aarch64-linux-ohos`;HAP 原生库目录虽沿用 `libs/arm64-v8a` 的 ABI 命名,但里面必须是 **用 HarmonyOS/OpenHarmony SDK 重新编译** 的 .so。直接塞入安卓 .so 会加载失败。**【较确定】**(来源 6、7、46)
- **可行性证据(好消息)**:
  - 社区项目 **sherpa-onnx**(基于 ONNX Runtime 的推理工具包)在 README 平台表中明确列出 HarmonyOS(x64/arm64/arm32 全支持),证明 ONNX Runtime 源码可在 OHOS 工具链下编译运行;社区亦有 2026-03 《鸿蒙上编译 ONNX Runtime 动态库》教程。**【较确定】**(来源 7、46)
  - **官方替代路线:MindSpore Lite**。MindSpore Lite 官方文档称其为"HarmonyOS 中系统内置的轻量化 AI 引擎",其模型转换工具**支持 ONNX 输入**(转 .ms 格式),支持 CPU/麒麟 NPU 后端。即:把现有 .onnx 模型转成 MindSpore .ms,再集成 MindSpore Lite(Native C API/ArkTS 侧)推理。**【确定】**(来源 8)
  - 华为还有 NNRt(神经网络运行时)等系统加速能力可作为执行后端。**【不确定】**(细节未逐一核实)
- **工作量判断**:若模型算子常见(Conv/Resize/池化等),MindSpore Lite 转换路线 3~7 人日可验证跑通;若坚持 ONNX Runtime,需 5~10 人日自编译 OHOS 版 .so 并踩坑。若模型用了少见算子,存在转换失败需改模型/改后处理的风险。**【较确定】**(经验估计,无官方承诺)

### 2.7 小结(纯血路径)

NEXT 上:包格式只有 HAP、必须 AGC 签名、只能走 AppGallery 分发;个人开发者(实名+软著+备案)**可以上架,不需要企业资质**;但现有工程基本归零重写(UI 必须 ArkTS,算法手工翻译,ONNX 需换 MindSpore Lite 或自编译),是"一个新 APP 项目",不是"移植"。

## 三、关键决策点:个人开发者、无企业资质,两条路径各能不能上?

| 路径 | 无企业资质能否上架应用市场 | 依据与确定性 |
|---|---|---|
| HarmonyOS 4.x 及以下(APK → AppGallery) | **能**。个人实名认证账号即可发布;需软著/电子版权证书 + APP 备案 | 华为官方账号/实名文档 + 多年上架实操 **【确定】** |
| 自分发 APK(HarmonyOS 4.x 设备直接安装) | **能**。与应用市场资质无关;建议域名+备案规范化 | 侧载机制公开 **【确定】**;备案边界 **【不确定】** |
| HarmonyOS NEXT(HAP → AppGallery) | **能**。个人开发者可注册、实名、申请发布证书、上架;同样需软著 + 备案 | 官方激励计划面向个人、个人全流程实操文章 **【较确定】**(建议上架前以 AGC 最新文档复核) |

**结论:"无企业资质"在两条路径上都不是拦路虎,不构成否决项。**真正的门槛是:(1) 软著与备案两样材料(钱少、主要是时间);(2) NEXT 路径的整包重写与 ONNX 迁移风险。

## 四、结论建议

### 4.1 现在就能做的最短路径(建议立即执行)

1. **继续以 APK 服务鸿蒙 4.x 及以下用户**:维持现有安卓包;在官网/网盘提供 APK 下载页(页面注明"适用于 HarmonyOS 4.x/EMUI;HarmonyOS 5/6/7(纯血鸿蒙)暂不支持,请关注原生版"),侧载指引写清"关闭纯净模式 + 授权未知来源"。**开发工作量:0~1 人日。**
2. **补两样资质,保留上架选择权**(软著申请周期最长,建议先启动):
   - 软件著作权登记(官方渠道免费,30~60 工作日)或第三方电子版权证书(数天,仅上架用);
   - APP 备案(需域名+国内服务器/接入商,约 100~300 元/年,2~4 周)。
   备齐后可随时把现有 APK 递交 AppGallery(个人账号即可),零开发成本获得商店流量。**工作量:2~4 人日(不含等待)。**
3. **纯血鸿蒙用户:先不承诺**。NEXT 用户暂时无法使用本 APP(无法侧载);可在下载页与 APP 内公告"鸿蒙原生版在研/规划中"。不建议为此仓促上跨端框架。

### 4.2 "做纯血鸿蒙版"分期路线图(供决策)

> 前提:个人开发者,ArkTS 从零学习;算法为纯 Java 零依赖(利好:可直接翻译,无第三方库替换负担);AI 推理是唯一硬骨头。

**阶段 0(资质并行线,与阶段 1 同时启动)**:软著 + APP 备案 + 华为个人开发者账号。0 开发工作量,等待期 2~8 周。

**阶段 1:ArkTS 原生精简版(验证可行性 + 可上架的 MVP)**,预估 **23~40 人日**

| 模块 | 内容 | 预估 |
|---|---|---|
| 环境+学习 | DevEco Studio、ArkTS/ArkUI 基础、状态管理 | 3~5 人日 |
| 选图/相册 | photoAccessHelper 选图、权限申请(相机可后置到阶段2) | 2~3 人日 |
| 算法移植 | Java 图像算法(量化/抖动/网格)手工翻译为 ArkTS | 3~5 人日 |
| 图纸渲染 | ArkUI Canvas 绘制拼豆网格、色号、图例 | 3~5 人日 |
| **ONNX 迁移(风险项)** | 优先:模型转 MindSpore Lite(.ms)+ 集成推理;备选:自编译 ONNX Runtime OHOS 版 | 5~10 人日 |
| 导出 | 图片存相册(1 人日);PDF:系统无 android.graphics.pdf 等价物的成熟公开方案,可自写轻量 PDF 生成(内嵌 JPEG)或找三方库 | 2~4 人日 |
| 设置/板型/持久化 | preferences、板型参数库 | 2~3 人日 |
| 签名/上架 | AGC 证书、打包、审核往返 | 2~4 人日 |

> 若允许"精简版"先用纯算法替代 AI 推理(如无 AI 时用常规量化),阶段 1 可压缩到 **15~25 人日**,AI 能力放阶段 2。

**阶段 2:完整迁移版**,预估 **15~25 人日**:相机实时取景、全部板型/色号库、导出完善、性能优化(必要时热点下沉 NDK C++)、NPU 加速(NNRt)、平板/折叠屏适配、国际化。

**总计:38~65 人日**(约 2~3 个月业余投入;若砍掉 AI 依赖可显著缩短)。决策建议:**先完成 4.1 与阶段 0;阶段 1 的第一周先做 ONNX 迁移的技术验证(5~10 人日风险前置),跑不通再决定砍 AI 还是换 MindSpore 模型转换。**

### 4.3 风险清单

1. ONNX→MindSpore Lite 转换的算子兼容性(最大技术风险,先验证)。
2. 软著下证周期影响上架时间(先用电子版权证书可解)。
3. 纯离线 APP 的备案边界解释存在灰色地带(上商店就必须备案,自分发暂无强制)。【不确定】
4. 个人开发者上架 NEXT 的官方条款细节可能更新(本文为较确定级,上架前以 AGC 文档复核)。
5. 鸿蒙 4.x 用户盘子逐年缩小,旧路径投入有自然衰减;但成本极低,可一直"挂着"。
