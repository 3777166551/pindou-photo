## 结论速览（TLDR）

1. 用户"没有别的 App 明亮清晰"**不是错觉**：`boxResample` 在 sRGB 伽马空间求均值（系统性变暗约 -4.3 L*）+ 色板匹配把亮区拉暗（L* 70~92 段平均 -5.2）+ 全程无自动增强/锐化 + 三个提清晰度开关默认全关。
2. "简单图案有杂色"**机制已实证**：跨色边界格被盒平均成第三色（红白→粉）。现状管线实测杂色 58~140 颗/图；"杂色清理"开关救不了（合并按区域主色，粉豆带自成区域）。
3. 修复方案经**后台测试台六题材×十管线自动评分**（[04-后台测试报告.md](04-后台测试报告.md)）定论：**"先配后投"（逐像素配豆→格内众数豆）以 10.9 分对现状 34.6 分断层第一**——0 杂色、买豆用色省 3~8 倍、像素画原色保真 91%（现状 29%）、五官细节 100%、照片保真持平；全局众数（11.2）与其同档。混合方案（双峰检测）在噪声下失效已否决；FS 抖动默认关是对的；全局"一键美化"不适合默认。
4. 业界对标（GitHub 开源圈）：CIELAB/OKLab + CIEDE2000 是绝对标配；降采样普遍带线性光校正和边缘感知取色。我们骨架不差且多项领先（U²-Net 去背景、Lab 空间 FS 抖动），缺口全部是增量修改。

## 建议实施路线（2026-09-21 经后台测试台定论 + 用户 UX 拍板，待动码）

每步独立可验收、互不冲突。**主流程零新增选项**（用户原则：多一个选择=多一分不理解）：

1. **写实模式默认换"先配后投"** + 4096 项 RGB→豆色 LUT（Java 全图约百万次查表，毫秒级，兼容现有"秒切"缓存架构）——全部主要收益的来源；一套管线通吃全部题材，不做按题材选算法
2. **CIEDE2000 默认开**（配缓存；"精准配色"开关语义反转为"快速 Lab 欧氏"档）——业界标配，但测试显示收益次要
3. **图形/照片二分类 → 仅照片欠曝时自动温和提亮**（只提亮不压暗、增益≤1.35、饱和×1.10、平均亮度≥125 不干预）；分类阈值用真机图库标定（同去背景 v6 方法）；误判代价有界（同色区仍同豆，不会乱）。实测图形四题材与不提亮逐格一致
4. 抖动维持默认关、杂色清理维持现状（测试台已验证默认关是对的）
5. 现有滑杆全部收进"高级"面板，主界面零暴露；黑白锚点为低优先级打磨项；抽象 brick 平均与去背景掩码平均改线性光（服务抽象模式）
