# 04 · 后台测试报告：哪种算法最符合拼豆人习惯（2026-09-21）

> 测试台：`probes/algo_bakeoff.py`（纯 Python、无 UI、无真机，42 秒跑完全部组合）
> 结果原文：`probes/bakeoff_result.txt`（六题材 × 十管线完整数据）
> 结论已按三轮迭代收敛：第一轮发现两处指标不公平（ΔE 参照物自比、平坦类误用混合参照）已修正；"一键增强"从激进对比度拉伸改为真实语义的"只提亮+饱和"再对比。

## 一、测试设计

### 题材 = 拼豆社区六类高频输入（58×58 默认网格）

| 题材 | 对应拼豆人场景 | 专属真值指标 |
|---|---|---|
| 卡通（红体+黄肚+黑眼，白底） | 角色图纸（社区最大类） | 杂色数 |
| 简笔画（黑描边+红块） | 线条图案图纸 | 杂色数 |
| 像素画（5 色马赛克，故意错位网格） | 像素画还原 | 原色保真率 |
| 风景照（渐变天+草地噪声） | 照片写实图纸 | ΔE 保真 / L* 亮度 |
| 人像（肤色脸+头发+眼嘴） | 人物照片图纸 | 五官细节保留率 |
| 字牌（三条横杠 logo，最细 8px） | 字/logo 图纸 | 细节保留率 + 杂色数 |

### 指标 → 拼豆人习惯的映射（计分权重）

- **杂色**（0.26）+ **碎豆**（0.16）：图纸干净度 = 买了没用的豆、拼完发花
- **细节**（0.16）：五官/字条是否配对正确豆 = 图纸"像不像"
- **原色保真**（0.14）：像素画党要求色号一一对应
- **用色**（0.12）：买豆种类 = 成本和找豆时间，越少越省
- **ΔE 保真**（0.45）+ **L* 亮度**（0.15）：仅照片类计分（成品像不像原照）
- 连通区数仅打印不计分：同色连通块越少 = 填格子越顺
- **平坦类题材不用"混合平均色"当保真参照**——幻影混合色正是要消灭的对象，用混合色当尺会反过来奖励杂色管线（第一轮已修正）

## 四、四个次级结论

1. **CIEDE2000 vs Lab 欧氏：本次测试基本打平**（10.9 vs 11.0）。仍建议默认 CIEDE2000（业界标配、LUT 后无成本），但别指望它是主要收益来源——主要收益全部来自"先配后投"。
2. **FS 抖动默认关是对的**：V10 在所有平坦题材全面变差（卡通杂色 196、用色 28、同色连通块 185），照片上 ΔE 也更差（11.64）。维持手动开关。
3. **全局"一键美化"不适合默认**：即便温和的只提亮+饱和版，在饱和色上仍会平移色相（像素画原色保真 32%、卡通杂色 177）；激进的对比度拉伸版本直接垫底（杂色 2166、五官 0%）。美化应留给用户手动滑杆；若未来做预设，必须"只提亮"且避开平坦类题材。
4. **黑白锚点无实测收益但也无害**（V8 与 V4 得分相同）：测试场景里近白/近黑混合格太少，未触发。保留为低优先级打磨项。

## 五、最终建议（更新版实施顺序）

1. **写实模式默认改"先配后投"**（4096 项 LUT）——本轮全部收益的来源
2. **CIEDE2000 默认开**（顺手，业界标配，但收益次要）
3. 抖动维持默认关；杂色清理维持现状
4. 黑白锚点：低优先级打磨
5. 不做默认美化；抽象 brick/去背景掩码的线性光平均仍值得做（这是 mean 路径的修正，服务于抽象模式）

## 七、增补：颜色统一性压力测试（用户追问"简单色/简单图案会不会乱"，2026-09-21）

测试台 `probes/uniformity_probe.py`：纯色红盘+白底，格内矩形取样（含部分圆外白底作对照），对比 现状 / 先配后投 / 先配后投+孤格吸附：

| 压力 | 现状红区用色 | 先配后投红区用色 | 结论 |
|---|---|---|---|
| JPEG 块状噪声 ±4 | 8 种（含浅粉/珊瑚红幻影色） | **2 种（大红+白，0 幻影）** | 投票完全统一 |
| JPEG 块状噪声 ±8 | 9 种 | **2 种** | 仍完全统一 |
| JPEG 块状噪声 ±14（极重） | 11 种 | 3 种：大红+白+**7 颗番茄红（0.5%）**，孤格吸附后回到 2 种 | 极端噪声下偶发翻面，现有"杂色清理"即可吸收 |
| 渐变白底 255→215 | 2 色干净分带 | 2 色干净分带（与现状逐格相同） | 不更乱，海报化分带两算法一致 |
| 两豆之间的深红源色 | 酒索单色+9 种杂 | 酒索单色（区内） | 无摇摆 |

**回答**：先配后投在简单色/简单图案上**更统一而不是更乱**——机制上每格是几十个像素的多数票，同一片纯色的格子像素分布几乎相同→投出同一颗豆；幻影杂色被整体消灭后，"杂色清理"开关对残余孤格才真正生效（它救不了旧的边缘杂色带，但救得了孤点翻面）。全图用色：现状 8~11 种 vs 投票 2~3 种。

## 八、增补：产品化定稿——零新增选项 + 图形/照片二分（用户决策，2026-09-21）

用户拍板 UX 原则：多数拼豆用户是轻松休闲玩家，**多一个选择=多一分不理解**。据此定稿：

**① 取色算法不做题材区分**。测试台证明"先配后投"一套通吃六类题材（卡通/简笔画/像素画/风景/人像/字牌全部第一或并列第一），按题材换算法只增加复杂度没有收益。主流程 = 一条管线 + 全自动。

**② 图形/照片二分类，只驱动一个决策：要不要自动提亮**。
- 图形（色桶少）：原色神圣，不做任何画面调节 → V11 与 V6 在卡通/简笔画/像素画/字牌上**逐格完全一致**（实测）
- 照片且欠曝（平均亮度<125）：自动温和提亮（只提亮不压暗、增益≤1.35、饱和×1.10）→ 实测欠曝场景 L* +9.8
- 照片且曝光正常：不干预（实测风景照/人像 V11≡V6）
- 分类特征：4-bit 色桶数（阈值 64）。**注意：合成场景色桶天然偏少（30~62），绝对阈值必须用真机图库标定**（与去背景 v6 用后台语料调校同一方法）；机制层（门控安全、误判有界）已由测试台证明
- **误判代价有界**：即使暗色图形被误判为照片，全局乘法提亮下同色区仍投同颗豆（先配后投保证），结果只是整体亮一档的干净图纸，绝不出现杂色混乱

**③ 现有滑杆（亮度/对比/饱和/抖动/杂色清理/精准配色）全部收进"高级"面板**，主界面零暴露。新用户：选图→出图，全自动；进阶用户：高级面板仍可细调。

测试台新增：V11 = 先配后投+CIEDE2000+仅照片自动提亮。最终排名（七题材）：V5 15.2 ≈ V6 15.4 ≈ **V11 15.4** ≈ V7 16.1，断层领先现状 35.6（得分体系把"故意的提亮"记为偏差，属指标语义非缺陷）。

## 九、落地记录（2026-09-21，已动码）

**V11 方案已实现进 PatternEngine，写实模式默认生效**：

- `WorkGrid` 升级为缓存**每格源像素清单**（cellPix/cellStart）+ 门控参数；
- `buildVoteGrid`：源像素正向映射入格（与盒平均同覆盖），同时统计不透明亮度均值与 4bit 色桶数 → 桶数 ≥64 且均值亮度 <125 判"欠曝照片"，增益 = min(1.35, 125/L)、饱和 ×1.10（桶阈值 64 为初版，待真机图库标定）；
- `buildLut`：4096 项 RGB4bit→豆下标查找表（preciseColor 开 = CIEDE2000，关 = Lab 欧氏），换色板/限色只重建 LUT+重投票，秒级出图路径保持；
- `finishVote`：逐像素查 LUT 后**格内多数票**（含门控与手动滑杆的逐像素调节）；不透明不足半数 = 空格（与盒平均 alpha 阈值同语义）；
- 尾段（展开/形状蒙版/杂色清理/限色/统计）抽成 `finishPattern`，投票与均值两路径共用；
- **均值路径保留**：FS 抖动、去背景（gridWithBackground）、众数（dominantResample）、抽象/线稿仍走原盒平均管线——抖动的误差扩散语义只在均值世界成立；
- 零新增用户选项（§8 拍板）：门控全自动，滑杆全数留在"高级"折叠区；
- qa/TestPatternEngine 更新为投票语义 + 新增**多数票定义性测试**（3红1蓝投红）与空格比例测试，全套 364 项本地全绿。

已知边界：①合成场景桶数偏少的问题不影响 APP（真实照片桶数远高于 64）；②门控误判代价有界（§8 已证）；③抽象 brick 的线性光平均仍属待办（服务抽象模式，与本路径无关）。

### 指标体系(经 4 轮实测迭代 + 6 张目检校准,教训比结论值钱)

1. **无主豆格率**(主指标):格内没有任何源像素把该豆当最近色 = 无中生有的杂色。构造性度量、无阈值,NEW 机制上恒 0,OLD 的边缘晕染/幻影全被抓住——**全场唯一贯穿 347 张都成立的硬指标**。
2. **线保留**:dark 格数(L*<45)比,仅 lineart/cartoons 参与判决(<85% 报警)。实测仅 2 例报警且均为晕染清除的保守误报(目检 NEW 更好),进复核堆由人定夺。
3. **ΔE 对源图盒平均**:只作照片灾难护栏(恶化>+8)与报告列,**不能当逐图判决**——均值参照是 L2 最优,多数票的锐利输出结构性吃亏(非门控照片中位 +3.35、最大 +7.43);门控图再 +8~9.7(故意的提亮被记为偏离,L* 收益另报)。合成测试台当年"ΔE 持平"的结论只在平滑合成场景成立,真实纹理图不成立——**这是本基准抓到的合成基准盲区**。
4. **色相离群格**(报告列):豆色相与格内全部彩色像素(C*≥10)色相夹角>30°,抓"棕墨/灰图投异色豆"(目检实锤:sepia 雕版上的绿点);但在多色细胞上退化为纹理丰富度信号(照片 66~162 格/图),**不能自动判决**。
5. **碎豆v2**(非深豆 ≤2 格碎片):曾试当判决指标,目检证伪——把锐利边界的锯齿当杂色(4/6 样张 NEW 明显更好),降级为复核信号。教训:**结构代理度量不了"风格权衡"**。

2. **门控对深背景照片过度提亮**(蝴蝶图背景拉成淡黄)——桶阈值 64 待标定的实证。

### V12 试验(2026-09-21,用户复核堆反馈"纯色图 OLD 好"后的修正尝试)——负结果,已证伪

针对两个假设的修正(贴色调救援=深豆像素均色选豆;相似色孤格吸附 ΔE<12),347 张三管线对照:**V12 与 V11 全指标重合**(dark 比 2.52/2.52、碎豆v2 38.3/38.2、用色/ΔE 不变,目检逐格几乎相同)。归因:
1. 贴色调无效——rescue 的深豆子集很紧凑(全是 L*<45 的豆),其均色的最近豆=深豆众数本身;dark 2.5x 不是"救援选太黑",而是"救援触发范围大+OLD 的线本来就是灰晕没画出来"——dark 比高是正确行为的一部分;
2. 吸附无效——纯色区噪声翻点在真图上极罕见(uniformity probe 极端 ±14 噪声才 0.5%),且边界锯齿设计上不碰。
结论:"纯色图 OLD 好"的剩余解释=①OLD 晕染=免费抗锯齿的风格柔和感(与消灭幻影不可兼得,属取舍非缺陷);②门控深背景照片过度提亮(修复方向:门控亮度改中位数,待拍板);③灰度/棕墨扫描色度噪斑(修复方向:近灰源色度去噪,待拍板)。APP 代码与 CI 未动。算法无改动,数据在 judge12_results.csv。

### 阈值标定(方案③,auto_calibrate.py)——现行参数均在帕累托前沿,不改

单参数扫描×5 档(带参投票与 batch_compare 在现行参数下逐格自检一致):

- **门控(照片侧,random 50 张)**:桶阈值 32~128 触发率恒 54%、触发集完全相同——**照片侧桶阈值是死旋钮**(真照片桶数远超 128,它的作用只在排除图形类);真旋钮=亮度阈值:100→28%/112→44%/**125→54%**/138→66%/150→82%,触发集均亮度 72.6→107.3。125 触发的是真暗图(均亮 91),取值合理;深背景照片误提亮是"均值亮度分不清暗主体与暗背景"的机制局限,标定解决不了,根治思路=中位/高分位亮度(待拍板,暂不动)。
- **救援带(线稿侧,lineart+cartoons 99 张)**:上限 30~60 几乎零差异(dark 952→977)——**上限是死旋钮**;下限才是真旋钮:4% 过度救援(暗格 637→1076,+69%,碎豆v2 恶化到 34.6)、7%→1023、**10%→977**、15%→901、20%→844(救援最少)。10% 位于帕累托前沿中部,与 §11 定稿一致,**维持 10%~45% 不变**。
